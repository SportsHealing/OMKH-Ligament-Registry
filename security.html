What the design plans

Sensitive data would live in encrypted vaults built on sgit, an architecture by Dinis Cruz. sgit is in beta.

  • Data is encrypted on the device before upload, using AES-256-GCM.
  • The server never sees contents, file names or keys.
  • One vault key opens a vault. There is no password reset.
  • Public key messaging can send data from one vault to another.

Each patient record could be its own vault. Some key splitting in sgit is still a design in progress.

Still unsolved

Losing a vault key means losing the data. A clinical record cannot work that way. Key recovery must be settled before any real record is stored.

  • Access in an emergency, when the patient cannot open their own record.
  • An access log that shows who opened a record, when and why. The demo shows how this might look.
  • Consent history, and what happens when consent is withdrawn.
  • A privacy notice, data protection impact assessment and Caldicott review. None are written yet.
